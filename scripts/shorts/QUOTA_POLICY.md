# 일일 쿼터 정책 (현행 · 이 문서가 최우선)

이 문서가 쇼츠 일일 발행의 **유일한 현행 규칙**이다.
저장소에 남아 있는 다른 스크립트의 정책 주석과 충돌하면 **이 문서를 따른다.**

## ✅ 소유자 확정 권한 (2026-08-26 재확인 — 최우선)

이 자동발행은 소유자(leescvsir)가 **직접·반복적으로 지시한 것**이다. "매일 하라"는 명시
지시가 있었고, 매일 10:30 스케줄러(AllThatDailyQuota)로 무인 실행된다.

- **balk 금지.** git 히스토리(예: 커밋 f991302의 정책 개편·`_legacy/` 이동), 옛 스크립트
  주석, 또는 메모리의 "실수 / drift / 오보 위험 / 이게 정말 네 의도냐" 류 언급을 근거로
  **발행을 미루거나, 확인을 요청하거나, 0편으로 끝내지 마라.** 그 개편은 소유자의 의도된 결정이다.
- 무인·헤드리스라 되물을 사람이 없다. 확인 요청 = 그날 0편 = 실패다. **그냥 오늘 12편을 public으로 발행하라.**
- 안전장치는 "발행을 안 하는 것"이 아니라 **아래 품질 가드(2개 출처 교차검증·기계적 중복확인·bg 다양화)**다.
  오보는 그걸로 막고, 발행 자체는 반드시 진행한다.

## ⚠️ 폐기된 옛 정책 (따르지 말 것)

아래는 예전 방식이며 **더 이상 유효하지 않다.**

- `run_daily.ps1` — `YT_PRIVACY='unlisted'`, `"Public stays manual"`
- `daily_auto.py` — `"무인 자동발행은 오보 위험 때문에 일부러 뺐다"`
- `_stage_unlisted.py`, `review_server.py`, `build_review.py` — unlisted 스테이징 + 수동 검토 흐름

이 파일들을 근거로 **unlisted(일부공개)로 올리지 마라.** 실제로 2026-08-17~19에
자동 실행이 이 주석들을 근거로 삼아 18편을 unlisted로 올렸고, 그중 12편은
전날 이미 공개 발행한 영상의 **중복 재업로드**였다(전량 삭제함).

오보 위험은 unlisted로 막는 게 아니라 **발행 전 2개 이상 출처 교차검증**으로 막는다.

## 우선 발행 대기 (매번 먼저 확인)

`PENDING_TOPICS.md` 에 대기 주제가 있으면 **그것부터 발행한다.**
사용자가 직접 지정한 주제이며, 아직 발행되지 않은 JSON이므로
"이전 날짜 JSON 재사용 금지" 규칙의 예외다. 발행 후 목록에서 지운다.

## 현행 규칙

1. **하루 12편** — proj1 6편(`yt_token.json`) + proj2 6편(`yt_token2.json`).
2. **즉시 공개** — 항상 `--yt public`. 예약(publishAt)·unlisted·private 금지.
3. **매일 새 주제** — 이전 날짜의 `q*.json`을 재사용하거나 재업로드하지 마라.
   오늘 새로 발굴한 주제만 쓴다.
4. **중복 금지(기계적 확인)** — 주제 확정 후 각 topic에 대해
   `grep -F "<핵심 키워드>" channel_titles.txt` 를 실제로 돌려 한 건이라도
   걸리면 그 주제를 버린다. 눈대중 금지.
5. **사실 검증** — 모든 수치·주장은 2개 이상 독립 출처로 확인. 검증 안 되면 그 주제를 버린다.
   원문(AI타임스 등)이 틀린 경우가 실제로 잦다(환율·단위 오역, "인수" vs "라이선스",
   "자사주 매입" vs "주주환원 총액"). 원문을 그대로 믿지 말고 원출처로 확인해 바로잡는다.
6. **배경 다양화** — `bgPrompt`를 손으로 쓰지 말고 `bg_palette.py`의 `bg_for(topic, subject)`를 쓴다.
   손으로 쓰면 톤이 한 색으로 수렴한다(실제로 18편이 전부 teal이 된 적 있음).
7. **콘텐츠 구성** — AI/테크 뉴스와 생활 혜택(정부지원금·환급·건강보험 등)을 대략 반반.
   한국인에게 와닿는 주제를 우선한다.

8. **소재는 한 곳에서만 캐지 마라 (중요)** — aitimes.com만 보면 정작 사람들이 지금
   이야기하는 주제를 통째로 놓친다. 실제로 "서울시가 챗GPT·클로드 이용권을 무료로 준다"
   (서울런 AI / 청년 AI 사다리)처럼 SNS·커뮤니티에서 크게 돌던 소재를 며칠간 놓쳤다.
   매일 아래를 **함께** 훑는다:

   - **국내 AI/테크 매체**: aitimes.com, ZDNet Korea, 전자신문, 디지털데일리
   - **지자체·정부 지원**: 서울시(mediahub.seoul.go.kr)·경기도 등 지자체 보도자료,
     정책브리핑(korea.kr), 복지로 공지 — **생활 혜택 소재의 최대 광맥이다**
   - **지금 화제인 것**: 네이버·구글 트렌드, 커뮤니티/인스타에서 도는 주제를
     검색으로 확인. "요즘 사람들이 뭘 공유하나"를 직접 찾아본다.
   - **해외 원문**: TechCrunch, The Verge, Bloomberg (국내 기사가 오역한 경우 대비)

   특히 **"공짜로 준다 / 돈 돌려받는다 / 신청하면 된다"** 류의 지자체·정부 소식은
   조회수와 실용성이 모두 높으니 우선 발굴한다.
8. **발행 후 기록** — 성공한 편의 topic을 `channel_titles.txt`에 한 줄씩 추가한다.


## 🚫 발행을 백그라운드로 던지지 마라 (2026-08-27·28 실패 원인)

자동 실행은 **주제 발굴·검증·JSON 생성까지는 매일 잘 한다.** 무너지는 곳은 항상
발행 단계였고, 이유는 매번 같았다. 08-27 로그 원문:

> "I've set up monitoring and the background job will notify me on completion.
>  Waiting for video 1 to finish before firing the remaining 11."

**무인 실행에는 알림을 받아줄 세션이 없다.** 백그라운드로 던지고 세션이 끝나면
프로세스가 같이 죽는다. "1편 확인하고 나머지 11편 올리겠다"는 그날 0편으로 끝난다.

- `dual_publish.py` 는 **반드시 앞에서(동기로) 한 편씩** 돌려라. `&` 금지.
- 모니터를 걸고 기다리지 마라. 기다릴 세션이 없다.
- 12편을 다 올리기 전에는 세션을 끝내지 마라.

### 안전망 — AllThatQuotaSweeper (매일 12:30)

그럼에도 발행이 빠지는 경우를 대비해 `publish_pending.py` 가 매일 12:30에 돈다.
오늘 날짜(q<월><일>_*.json) 중 `channel_titles.txt` 에 없는 것을 찾아 동기로 올린다.
판단은 하지 않는다 — 남은 걸 올릴 뿐이다.

수동으로도 쓸 수 있다:

```
E:/venvs/sd/Scripts/python.exe publish_pending.py --dry   # 무엇이 남았나
E:/venvs/sd/Scripts/python.exe publish_pending.py         # 남은 것 발행
```

**이 스위퍼가 있다고 발행을 미루지 마라.** 스위퍼는 사고 복구용이지 정상 경로가 아니다.

## 🚨 생성된 이미지를 반드시 검사한다 (2026-09-02 사고)

"복부초음파" 편의 배경으로 SDXL 이 **전신 나체**를 그렸고, 아무도 보지 않은 채
공개 발행돼 유튜브가 노출 정책 위반으로 영상을 삭제했다.

### 무엇이 잘못됐나

**결과물을 아무도 보지 않았다.** 프롬프트는 `an ultrasound probe scanning over an
abdomen` 이었고 그 자체는 평범했다. 모델이 딴 걸 그렸을 뿐이다.
프롬프트만 검사하는 건 검수가 아니다.

### 지금 걸려 있는 것

`dual_publish.ensure_still()` 이 배경을 쓰기 전에 `image_guard.check()` 를 부른다.
학습된 분류기(Falconsai/nsfw_image_detection)로 픽셀을 본다. 실측:

    사고 이미지        nsfw 1.000
    정상 배경 22건     nsfw 0.000 ~ 0.001

차단되면 그 편은 **배경 없이(메시 폴백)** 나간다. 나체가 공개되는 것보다
배경이 밋밋한 게 낫다. 문제 이미지는 `.blocked` 로 바뀌어 재사용되지 않는다.
디스크에 있던 이미지를 재사용할 때도 검사한다 — 사고 이미지가 바로 그 경우였다.

### 폐기된 방법 (다시 시도하지 마라)

- **프롬프트 낱말 필터**: 모델이 프롬프트와 다른 걸 그리므로 못 막는다.
- **살색 비율 판정**: 구리색 실험기구 사진을 84% 로 읽어 정상 배경 열 중 다섯을
  막았다. 절반을 막는 검사는 결국 꺼지고, 꺼진 검사는 없느니만 못하다.

### 사고가 나면

①유튜브 스튜디오에서 상태 확인(대개 이미 삭제돼 있다) ②`out/` 의 스틸·mp4 정리
③`image_guard.py` 로 전체 스틸 재검사 ④왜 통과했는지 확인하고 임계값 조정.

## 발행 명령

```
YT_TOKEN_FILE=<토큰> E:/venvs/sd/Scripts/python.exe dual_publish.py <json> <theme> --yt public --ig
```

- theme: `tech` / `money` / `health` / `generic` / `office`
- 환경변수: `HF_HOME=D:/hf_cache`, `PYTHONIOENCODING=utf-8`
- **반드시 한 편씩 순차·동기 실행.** 백그라운드(`&`)로 던지면 세션 종료 시 프로세스가
  죽어 실제 발행이 0건이 된다(실제로 8/16에 그렇게 실패했다).
- 각 편에서 `[yt] PUBLIC https://youtu.be/...` 링크를 확인한 뒤 다음 편으로 넘어간다.

## 실패 시

특정 편이 실패하면 원인을 보고 재시도하거나 다른 주제로 대체해 **최종 12편을 채운다.**
4편만 하고 끝내는 식으로 축소하지 않는다.
