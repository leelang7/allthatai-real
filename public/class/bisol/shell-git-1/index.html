2. 셸 스크립트 기초

셸 스크립트 = 터미널에 칠 명령어를 순서대로 적어 둔 텍스트 파일. 위에서 아래로 한 줄씩 실행된다.

#!/bin/bash
echo "안녕하세요"
echo "오늘 날짜: $(date +%Y-%m-%d)"
echo "현재 위치: $(pwd)"
쓰기뜻
#!/bin/bash이 파일은 bash로 실행하라는 표시. 항상 첫 줄에 쓴다
# 으로 시작하는 줄주석. 실행되지 않는 메모
./hello.sh현재 폴더의 hello.sh를 실행. 실행 권한(x)이 필요하다
bash hello.sh실행 권한이 없어도 실행된다

변수와 따옴표

name="vision"
count=3
echo "$name 프로젝트, 이미지 $count 장"    # vision 프로젝트, 이미지 3 장
  • 만들 때는 이름=값, 쓸 때는 앞에 $. = 양옆에 공백을 넣으면 안 된다 (name: command not found)
  • 큰따옴표 "$name"은 변수를 값으로 바꾸고, 작은따옴표 '$name'은 글자 그대로 둔다
  • 파일 이름에 공백이 있을 수 있으니 변수는 항상 "$변수"처럼 큰따옴표로 감싼다

3. 조건과 반복

if

#!/bin/bash
if [ -f "$1" ]; then
    echo "$1 파일이 있습니다"
elif [ -d "$1" ]; then
    echo "$1 은 디렉터리입니다"
else
    echo "$1 이(가) 없습니다"
fi

[ 뒤와 ] 앞에는 반드시 공백. 위에서부터 차례로 묻고, 처음으로 참이 된 한 곳만 실행한다.

조건뜻조건뜻
[ -f 경로 ]파일이 있다[ -z "$변수" ]변수가 비어 있다
[ -d 경로 ]디렉터리가 있다[ "$a" = "$b" ]문자열이 같다
[ ! -f 경로 ]파일이 없다[ "$n" -ge 3 ]숫자가 3 이상이다

숫자 비교: -eq 같다 · -ne 다르다 · -gt 초과 · -ge 이상 · -lt 미만 · -le 이하

성공과 실패

  • 모든 명령어는 끝날 때 숫자를 남긴다. 0이면 성공, 0이 아니면 실패. echo $?로 본다
  • A && B — A가 성공하면 B 실행 / A || B — A가 실패하면 B 실행
  • exit 1 — 스크립트를 실패로 끝낸다 / set -e — 명령이 실패하면 스크립트를 멈춘다 (예외는 바로잡기 B-3)

for, while

for d in dataset/*/; do              # 폴더를 하나씩
  n=$(ls "$d" | wc -l)
  echo "$d : $n 장"
done

while IFS=, read -r file label worker; do   # CSV를 한 줄씩, 쉼표에서 잘라 변수 셋에
    echo "$file 은 $label ($worker 작업)"
done < labels.csv

위 for 문이 실습 2의 count.sh다. 결과: dataset/ng/ : 5 장, dataset/ok/ : 12 장, dataset/unknown/ : 3 장.

함수와 디버깅

count_images() {
    ls "$1" | wc -l          # 함수 안의 $1 은 함수가 받은 값
}
echo "ok: $(count_images dataset/ok) 장"

bash -x 파일.sh              # 실제로 실행되는 명령을 한 줄씩 보여 준다

4. 텍스트 처리

명령어하는 일예
cut열 잘라내기cut -d, -f2 labels.csv (쉼표로 나눈 2번째 열)
sort정렬-n 숫자로, -r 거꾸로, -k6 6번째 열 기준
uniq붙어 있는 같은 줄을 하나로 합친다uniq -c는 몇 번 나왔는지 세어 앞에 붙인다
awk열 뽑기, 조건으로 거르기, 합계awk '{print $2, $6}' train.log
sed글자 바꾸기sed 's/unknown/ng/' labels.csv

종류별로 몇 개인지 세는 공식

uniq는 붙어 있는 같은 줄만 합치므로 앞에 반드시 sort가 와야 한다. ✅ ok, ng, ok, ok 네 줄에 uniq만 쓰면 ok ng ok, sort | uniq는 ng ok가 나왔다.

awk

awk '{print $2, $6}' train.log              # epoch 번호와 정확도만
awk '$6 >= 0.85' train.log                  # 정확도 0.85 이상인 줄
awk -F, '$2 == "ng" {print $1}' labels.csv  # 라벨이 ng인 파일 이름 (-F, 는 쉼표로 나눔)
awk '{sum += $6} END {print sum / NR}' train.log   # 정확도 평균 0.784
sort -k6 -rn train.log | head -1            # 정확도가 가장 높은 epoch → epoch 4 ... acc 0.88

awk 안의 $1은 스크립트 인자가 아니라 "1번째 열"이다. 그래서 awk 명령은 작은따옴표로 감싼다.

sed

쓰기뜻
sed 's/a/b/'줄마다 처음 나오는 a만 b로
sed 's/a/b/g'줄 안의 모든 a를 b로
sed '1d'1번째 줄 삭제
sed -i 's/a/b/' 파일화면에 출력하지 않고 파일을 직접 고친다. 되돌릴 수 없으니 복사본을 만든 뒤에 쓴다

실습 3 (한 줄로 답하기)

cut -d, -f3 labels.csv | sort | uniq -c | sort -rn | head -1   # 가장 많이 라벨링한 작업자 → 4 kim
awk -F, '$3 == "kim" && $2 == "ok"' labels.csv                 # kim이 ok로 라벨링한 줄
awk '$4 < 0.5 {print $2}' train.log                            # loss가 0.5보다 작은 epoch → 3, 4, 5
sort -k4 -n train.log | head -1                                # loss가 가장 낮은 epoch → epoch 4
sed 's/img_/part_/' labels.csv > new.csv                       # img_ 를 part_ 로 바꿔 저장

9. 저장하기: init · status · add · commit

cd ~/vision-inspect

.git 폴더에 모든 이력이 들어 있다. 이 폴더를 지우면 이력이 전부 사라진다.

파일이 지나가는 세 곳

git add → git commit → 저장소로 간다. 택배에 비유하면 add는 상자에 넣기, commit은 송장을 붙여 보내기다.

파일의 네 가지 상태

git status              # 지금 상태 보기. 가장 자주 치는 명령
git status -s           # 짧게: ?? 새 파일, A 담김, M 수정됨
git add README.md       # 담기
git add .               # 현재 폴더의 바뀐 파일을 모두 담기
git commit -m "README 추가"
[main (root-commit) 172d42c] README 추가
 1 file changed, 2 insertions(+)
출력의 부분뜻
main브랜치
172d42c커밋 번호(해시). 사람마다 다르다
README 추가커밋 메시지

커밋 메시지

  • 나쁜 예: 수정, asdf, 최종 — 나중에 무엇을 했는지 알 수 없다
  • 좋은 예: count.sh 추가: 폴더별 이미지 수 세기 — 한 줄로 무엇을 했는지 쓴다
  • 한 가지 일을 끝낼 때마다 커밋한다. 여러 일을 한 커밋에 섞지 않는다

커밋 안에 든 것

  • Git은 바뀐 줄이 아니라 그 순간의 프로젝트 전체를 기록한다(스냅샷). 바뀌지 않은 파일은 다시 저장하지 않고 이전 것을 가리킨다
  • cat .git/HEAD → ref: refs/heads/main (지금 서 있는 곳)
  • cat .git/refs/heads/main → 커밋 해시 한 줄. 브랜치는 커밋 하나를 가리키는 이름표다

10. 이력 보기: log · show · blame · diff

명령보여 주는 것
git log커밋마다 해시, 작성자, 날짜, 메시지. q로 빠져나온다
git log --oneline커밋 하나를 한 줄로
git log --stat커밋마다 어떤 파일이 몇 줄 바뀌었는지
git log -p커밋마다 바뀐 내용까지
git log -3최근 3개만
git log -- count.sh이 파일을 건드린 커밋만
git show 해시커밋 하나를 자세히
git blame count.sh파일의 줄마다 마지막으로 고친 커밋과 사람
git diff고쳤지만 아직 담지 않은 변경. - 지워진 줄, + 새로 들어간 줄
git diff --staged이미 add 한 것의 변경

과거 다녀오기, 파일 하나만 되살리기

git switch --detach 7123d24             # 그 커밋 시점으로 이동 (구경만 한다)
git switch -                            # 원래 브랜치로 돌아온다

git show 7123d24:count.sh               # 그때의 파일 내용을 화면으로만 확인
git restore --source=7123d24 count.sh   # 파일 하나만 그때 내용으로 되돌린다
git restore count.sh                    # 방금 되돌린 것을 취소 (마지막 커밋 내용으로)

확인 문제

문제정답
git add와 git commit의 차이add는 스테이징 영역에 담기, commit은 담긴 것을 메시지와 함께 저장소에 기록

add 한 뒤 git diff가 비어 있는 까닭git diff는 담지 않은 변경만 본다. 담은 것은 git diff --staged

12. 🔍 슬라이드 바로잡기

슬라이드에서 틀렸거나 지금 환경과 다른 부분을 모았습니다. 슬라이드와 이 표가 다르면 이 표를 기준으로 보세요.

#슬라이드 내용바로잡기
B-1Git 1: "어제 만든 스크립트", "어제 만든 count.sh"셸 스크립트와 Git을 같은 날 했으므로 "오늘 오전에 만든"이 맞다.
B-2for f in dataset/ng/*.jpg맞는 파일이 하나도 없으면 반복을 건너뛰지 않는다. ✅ 빈 폴더에서 실행하니 파일: empty/*.jpg가 한 번 출력됐다. 파일을 옮기거나 지우는 스크립트라면 반복 안에서 [ -f "$f" ]로 확인한다.
B-3set -e = "하나라도 실패하면 전체를 멈춘다"멈추지 않는 경우가 있다. ✅ ls nope.txt || echo 없음, if ls nope.txt; then, ls nope.txt | wc -l 세 줄을 지나 스크립트가 끝까지 실행됐다. ||·&&로 이은 명령, if의 조건, 파이프의 마지막이 아닌 명령의 실패는 멈춤 대상이 아니다.
B-4sort -k6 -rn = "6번째 열을 기준으로"-k6은 "6번째 열부터 줄 끝까지"가 기준이다. train.log는 6번째가 마지막 열이라 결과가 같다 ✅. 뒤에 열이 더 있는 파일이면 -k6,6으로 쓴다.
B-5n=$(ls "$d" | wc -l) = 이미지 수정확히는 폴더 안 항목 수다. jpg가 아닌 파일이나 하위 폴더가 있으면 같이 센다. 실습 데이터에는 jpg만 있어 맞는다. jpg만 세려면 ls "$d"*.jpg | wc -l.
B-6Git 1: "바뀌지 않은 파일은 복사하지 않고 … 용량도 늘지 않는다"바뀌지 않은 파일은 맞다. 바뀐 파일은 새 판이 통째로(압축되어) 저장되므로 그만큼은 늘어난다. 큰 데이터 파일을 자주 바꿔 커밋하면 저장소가 커진다.
B-7wget = "현재 폴더에 내려받기"빠진 것: 같은 이름의 파일이 이미 있으면 덮어쓰지 않는다. ✅ setup.sh를 두 번 받으니 setup.sh.1이 생겼다. 다시 받을 때는 먼저 지운다.

13. ➕ 더 알아보기 (슬라이드에 없음)

13-1. loss와 acc 읽기

epoch 4 loss 0.391 acc 0.88
epoch 5 loss 0.402 acc 0.86

실습 데이터에서 epoch 5는 4보다 loss가 올라가고 acc가 내려갔다. 오래 학습할수록 항상 좋아지는 것은 아니다. 그래서 sort -k6 -rn train.log | head -1로 가장 좋았던 epoch를 찾는다.

13-2. 스크립트 맨 위에 적어 두는 안전장치

#!/bin/bash
set -e                      # 명령이 실패하면 멈춘다 (예외는 바로 위 표 B-3)
if [ -z "$1" ]; then        # 인자가 없으면 사용법을 알려 주고 끝낸다
    echo "사용법: $0 [폴더]"
    exit 1
fi

13-3. uniq를 줄여 쓰기

✅ sort 파일 | uniq와 sort -u 파일은 같은 결과가 나왔다. 개수가 필요할 때만 sort | uniq -c를 쓴다.

13-4. add 한 뒤에 또 고치면

git add README.md
(README.md를 또 고침)
git status -s        # AM README.md

✅ 왼쪽 글자는 담긴 것, 오른쪽 글자는 담은 뒤에 또 바뀐 것이다. 이대로 커밋하면 add 한 시점의 내용만 기록되고 뒤에 고친 것은 남는다. 다시 git add 해야 들어간다.

13-5. git commit -am

git commit -am "메시지"는 add와 commit을 한 번에 한다. ✅ 단, 이미 추적 중인 파일만 담는다. 새로 만든 파일(??)은 들어가지 않고 "nothing added to commit but untracked files present"가 나왔다. 새 파일은 git add가 먼저다.

13-6. Git에 올리면 안 되는 것

오늘 만든 dataset/ 같은 이미지 데이터, 모델 파일, 로그, 비밀번호가 든 파일은 커밋하지 않는다. 제외하는 방법(.gitignore)은 Git 1의 뒷부분에서 배운다.
