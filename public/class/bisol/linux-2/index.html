PART 3. 알고 쓰는 리눅스 명령어

1. 정규표현식 📄📝

정규 표현식(Regular expression): 특정한 규칙을 가진 문자열의 집합을 표현하는 형식. 일부 문자는 특별한 뜻을 가진 기호(메타 문자)이고, 나머지는 일반 문자다.

메타 문자

메타 문자의미메타 문자의미
^문자열의 시작\d숫자
$문자열의 끝\D숫자가 아닌 것
.문자 하나\w알파벳 대소문자, 숫자, 언더스코어(_)
\s공백 문자\W\w에 해당하지 않는 글자
\S공백 문자가 아닌 것\n개행(줄바꿈) 문자
\메타 문자를 문자 그대로 사용\t탭 문자

선택 패턴

패턴의미
A|BA 또는 B (or). alice|elice는 alice 또는 elice
[ ]대괄호 안의 문자 중 하나
[0-9]숫자 하나
[a-z] / [A-Z]알파벳 소문자 하나 / 대문자 하나
[^0-9]숫자가 아닌 문자 하나 — [ ] 안의 ^는 not

^는 자리에 따라 뜻이 다르다: 패턴 맨 앞이면 "문자열의 시작", [ ] 안 맨 앞이면 "not".

수량 한정자

수량자의미수량자의미
?0개 또는 1개{n}n개 ({8} = 8개)
*0개 이상{n,m}n개 이상 m개 이하 (a{1,3})
+1개 이상{n,}n개 이상 (a{1,})

그룹 패턴

( )는 그룹. 전체 패턴 안에서 하나로 묶이고, 만든 순서대로 \1, \2…로 다시 참조할 수 있다. (to)ma\1은 tomato와 매칭된다 ✅.

사용 예: 전화번호

조건 — 010으로 시작, 가운데 자리는 네 자리, 구분 문자는 있을 수도 없을 수도 있다.

^010(\D?\d{4}){2}
  • ^010 — 010으로 시작
  • \D? — 숫자가 아닌 문자가 0개 또는 1개 (바로잡기 B-3)
  • \d{4} — 숫자 4개
  • (…){2} — 앞의 그룹이 2번

✅ 직접 확인: 010-1234-5678, 01012345678, 010.1234.5678은 매칭되고 011-1234-5678, 010-123-4567은 매칭되지 않았다.

2. grep 📄

파일에서 지정한 패턴이나 문자열을 찾아, 그 패턴을 포함한 행을 모두 출력한다.

grep [option] [pattern] [파일명]
옵션의미
-i대소문자를 구분하지 않고 검색
-v패턴과 일치하지 않는 행 출력
-c일치하는 행의 개수 출력
-w단어 단위로 일치해야 출력
grep elice hello.txt              # elice가 들어 있는 행
grep -c elice hello.txt           # elice가 들어 있는 행의 수
grep [0-9] hello.txt              # 숫자가 있는 행
grep "Elice\.The\.Rabbit" *       # 현재 디렉터리 모든 파일에서 Elice.The.Rabbit 찾기
grep -v ^# somecode               # #으로 시작하지 않는 행
grep '\<[a-z].*e\>' elice         # 소문자로 시작해 e로 끝나는 단어가 있는 행

➕ \<, \>는 단어의 시작과 끝을 뜻한다(GNU grep). 패턴은 따옴표로 감싸는 습관이 안전하다 → 바로잡기 B-5, B-6

실습(Linux-basic3 q1): address.txt 주소록 100개에서 이니셜 MAD의 전화번호를 grep으로 찾기.

3. File Redirection 📄

표준 스트림의 흐름을 바꿔, 화면·키보드 대신 파일로 입출력을 재지정하는 것.

번호스트림기본 연결
0stdin (표준 입력)키보드 입력
1stdout (표준 출력)화면 출력
2stderr (표준 에러)오류 내용 출력
ls > ls.txt                  # 표준 출력을 파일로 (파일이 있으면 덮어쓴다)
ls >> ls.txt                 # 파일이 없으면 만들고, 있으면 지우지 않고 이어 쓴다
cd helloelice > err.txt      # 오류는 화면에 그대로 나오고 err.txt는 비어 있다
cd helloelice 2> err.txt     # 오류(2번)를 err.txt에 저장
cat < hello.txt > elice.txt  # hello.txt를 cat의 입력으로, 출력은 elice.txt에 저장

✅ 직접 확인: cd nope > err.txt 뒤 err.txt 크기는 0, cd nope 2> err.txt 뒤에는 오류 문장이 파일에 들어갔다.

실습(Linux-basic3 q2): input.txt를 add.py의 입력으로 넣고 결과를 output.txt에 저장.

python add.py < input.txt > output.txt

4. Pipe 📄

둘 이상의 명령을 묶어, 앞 명령의 표준 출력을 뒤 명령의 표준 입력으로 연결한다. 기호는 |.

head a.txt | grep [0-9]               # 첫 10줄 중 숫자가 있는 행
head a.txt | grep [0-9] > result.txt  # 그 결과를 파일로 저장
ls | grep user01 > output.txt         # 이름에 user01이 들어간 항목만 저장
연결 대상예
Redirection명령 ↔ 파일python add.py < input.txt
Pipe명령 ↔ 명령cat input.txt | python add.py

실습(Linux-basic3 q3) ✅ 두 방식 모두 같은 결과가 나온다.

cat input.txt | python add.py > output.txt

5. mount 📄

물리적인 저장 장치(보조기억장치)를 디렉터리에 연결하는 것.

mount [option] [device] [directory]
df        # 현재 mount된 디스크 정보 출력
옵션의미
-a/etc/fstab에 적힌 파일 시스템을 마운트
-t파일 시스템 유형 지정 (생략하면 /etc/fstab 참조)
-o추가 설정. 여러 개는 콤마(,)로 구분

※ 마운트 해제 명령은 슬라이드의 remount가 아니라 umount → 바로잡기 B-9

PART 4. 프로세스와 네트워크

6. 프로세스 📄

프로세스 = 메모리에 적재되어 실행되고 있는 프로그램.

  • 모든 프로그램은 실행될 때 하나 이상의 프로세스를 갖는다
  • 병행적으로 실행할 수 있다
  • 부모·자식 프로세스가 있다
  • 커널이 관리한다
  • 모든 프로세스에는 소유자가 있다
  • 프로세스마다 식별용 ID(PID)가 부여된다

PID 1번은 init 프로세스(나머지 시스템 프로세스의 부모), 2번은 kthreadd → 바로잡기 B-10

프로세스의 메모리 구성

영역내용
코드 영역프로그램 코드
데이터 영역전역 변수와 정적 변수
BSS 영역초기화되지 않은 변수
힙 영역동적 메모리 할당 영역
스택 영역함수 매개변수, 복귀 주소, 지역 변수 같은 임시 자료

7. 프로세스 명령어: ps, kill 📄

ps            # 현재 터미널의 프로세스 목록
ps -ef        # 모든 프로세스 (UID, PID, PPID, CMD …)
ps -aux       # 모든 프로세스 (%CPU, %MEM 포함)
ps 옵션의미
-e실행 중인 모든 프로세스
-f모든 정보(전체 형식)
-a전체 사용자의 프로세스
-u실행한 사용자와 시작 시간 등
-x터미널 제어 없는 프로세스까지
kill [option] [PID]
kill -l       # 사용 가능한 시그널 목록
kill -9 PID   # 강제 종료 (SIGKILL)
kill -15 PID  # 정상 종료 (SIGTERM)
kill -1 PID   # SIGHUP

실습(Linux-basic4 q1): ps로 makeprocess.out의 PID를 찾아 kill로 종료. ➕ 한 줄로 찾기: ps -ef | grep makeprocess (PART 3의 파이프 + grep)

8. job 📄

  • job = 터미널에서 실행한 작업. 프로세스 전체가 아니라 그 터미널의 작업만 뜻한다
  • 터미널마다 job은 따로 있고, 터미널이 종료되면 job의 프로세스도 종료된다
  • 명령 뒤에 &를 붙이면 백그라운드로 실행, jobs로 목록 확인, kill %작업번호로 종료
sleep 500 &
sleep 700 &
jobs          # [1]- Running  sleep 500 &   /  [2]+ Running  sleep 700 &
kill %1
jobs          # [1]- Terminated  sleep 500  /  [2]+ Running  sleep 700 &

✅ 위 출력은 직접 실행해 확인했다.

10. SSH 📄📝

  • SSH(Secure Shell): 네트워크로 다른 컴퓨터에 접근하거나 그 컴퓨터에서 명령을 실행하게 해 주는 프로토콜
  • Telnet도 같은 일을 하지만 패킷이 암호화되지 않아 비밀번호 등이 노출된다. SSH는 데이터가 암호화된다
  • 우분투는 openssh 패키지로 SSH를 쓴다. 기본으로는 openssh-client만 있고, 다른 컴퓨터에서 접속받으려면 openssh-server를 설치해야 한다

수업에서 한 순서 📝

# 1) 패키지 목록 갱신
sudo apt update

# 2) 서버 설치
sudo apt install openssh-server

# 3) 서비스(서버) 구동
sudo service ssh start

# 4) 내 리눅스에서 구동 중인 서비스 확인 (+ 표시가 실행 중)
service --status-all | grep +

# 5) 네트워크 도구 설치 후 포트 상태 확인 (ssh는 22번 포트)
sudo apt install net-tools
netstat -tnlp

# 6) 클라이언트(Windows cmd)에서 접속
ssh 계정명@아이피

설치 여부 확인 📄: dpkg -l | grep openssh

12. 🔍 슬라이드 바로잡기

슬라이드에서 틀렸거나 지금 환경과 다른 부분을 모았습니다. 슬라이드와 이 표가 다르면 이 표를 기준으로 보세요.

#슬라이드 내용바로잡기
B-1"Reqular expression"Regular expression의 오타
B-2\W = "/w에 해당하지 않는 글자"슬래시가 아니라 역슬래시: \w
B-3\D? = "숫자가 아닌 문자가 0개 이상"?는 0개 또는 1개 (같은 자료의 수량 한정자 표와도 다르다). 0개 이상은 *
B-4수량자 표의 {n, m}, {n, }실제로는 공백 없이 {n,m}, {n,}
B-5정규식 표(\d, |, +, { }, ( ))를 배운 뒤 바로 grep 사용기본 grep에서는 표의 문법이 그대로 통하지 않는다. ✅ grep '\d{4}'는 아무것도 못 찾았다. |, +, ?, { }, ( )는 grep -E, \d·\D까지 쓰려면 grep -P. ✅ grep -P '^010(\D?\d{4}){2}'와 grep -E '^010([^0-9]?[0-9]{4}){2}'는 같은 결과
B-6grep [0-9] hello.txt처럼 따옴표 없는 패턴현재 폴더에 1 같은 한 글자 숫자 이름의 파일이 있으면 셸이 [0-9]를 그 파일 이름으로 바꿔 버린다. grep '[0-9]' hello.txt처럼 따옴표로 감싼다
B-7> = "표준 출력을 재지정"맞지만 빠진 것: 파일이 이미 있으면 내용을 지우고 덮어쓴다. 보존하려면 >>
B-8"리눅스의 경우 PnP 기능이 작동하지 않아 직접 연결해야 함"서버·최소 설치 환경에서는 직접 mount하지만, 데스크톱 우분투는 USB를 꽂으면 자동으로 마운트해 준다
B-9remount [device] [directory] = "mount를 취소하는 명령어"마운트 해제는 umount. remount는 명령어가 아니라 mount -o remount처럼 쓰는 옵션(옵션을 바꿔 다시 마운트)
B-10"PID 1번은 init, 2번은 kthreadd", "thread 프로세스는 모든 스레드의 부모"요즘 우분투의 1번은 systemd다(/sbin/init이 systemd로 연결). kthreadd는 모든 스레드가 아니라 커널 스레드의 부모. ✅ 수업용 WSL에서는 1번이 systemd였고 2번은 kthreadd가 아니라 WSL의 init 프로세스였다 — 환경마다 다르다
B-11kill -1 = "재실행(SIGHUP)"SIGHUP은 원래 "터미널 연결 끊김" 신호. 많은 서버 프로그램이 이 신호를 받으면 설정을 다시 읽도록 만들어져 있을 뿐, 모든 프로세스가 재실행되는 것은 아니다. 옵션 없는 kill PID는 15(SIGTERM)다. 먼저 15로 시도하고 안 될 때 9
B-12job = "백그라운드로 실행되는 작업을 보여주는 명령어"보여주는 명령어 이름은 jobs. job은 작업 자체를 가리킨다
B-130, 30 1 * * 0 /home/elice/backup.sh콤마 뒤 공백 때문에 칸이 하나씩 밀려 잘못된 줄이 된다. 0,30 1 * * 0 …
B-14sudo netstat -antp, sudo service ssh start동작은 하지만 요즘은 ss -tnlp, sudo systemctl start ssh를 더 많이 쓴다. ✅ 수업용 WSL에는 ss가 기본으로 있었다
B-15"OpenSSH Clinet"Client의 오타

13. ➕ 더 알아보기 (슬라이드에 없음)

13-1. grep 실전 옵션

13-2. 오류까지 한 파일에 저장

명령 > out.log 2>&1      # 표준 출력과 표준 에러를 모두 out.log에
명령 2> /dev/null        # 오류 메시지 버리기
명령 | tee out.log       # 화면에도 보이고 파일에도 저장

13-3. 포그라운드 ↔ 백그라운드 전환 (슬라이드 그림에만 있고 명령은 없음)

  • Ctrl + Z — 실행 중인 작업을 일시 정지
  • bg — 정지한 작업을 백그라운드에서 계속 실행
  • fg %1 — 1번 작업을 포그라운드로 가져오기
  • nohup 명령 & — 터미널을 닫아도 계속 실행 (8장의 "터미널이 종료되면 job도 종료"를 피하는 방법)

13-4. 프로세스 실시간으로 보기

top (종료는 q) — CPU·메모리를 많이 쓰는 프로세스를 실시간으로 본다. pkill 이름은 PID 대신 이름으로 종료한다.

13-5. Kaggle과 Colab

  • Kaggle (kaggle.com) — 데이터 분석·머신러닝 대회와 공개 데이터셋이 모여 있는 사이트
  • Google Colab — 브라우저에서 쓰는 파이썬 노트북. 설치 없이 GPU를 빌려 쓸 수 있고, 뒤에서는 리눅스가 돌아간다. 셀에서 !ls, !pwd처럼 !를 붙이면 오늘 배운 리눅스 명령어를 그대로 쓸 수 있다
